## Scope

Implement ER-021–ER-025, including the endpoint recovery prerequisite ER-021A:
event detail, paginated attempts, guarded replay, endpoint inspection/re-enabling, and a React dashboard.
The dashboard shows endpoints, recent events, persisted delivery attempts and replay results.
Inspection uses stored facts. Endpoint delivery statistics describe observed attempts in a stated window;
they are not synthetic endpoint probes or a guarantee of future availability.

API keys, multi-tenancy, ingest idempotency and rate limits remain M5. Retention, production deployment,
ordering and new delivery metrics remain M6. Endpoint deletion and secret rotation are outside this phase.

## Preserve the merged contracts

- PostgreSQL remains authoritative. Redis is bounded transport; publication failure must not undo an
  accepted durable replay, and due-event recovery must dispatch it after Redis returns.
- Preserve M3 classification, uniform jitter, Retry-After precedence/cap, expiry accounting and exactly
  `attempts_exhausted`, `non_retryable_response`, `non_retryable_policy` as terminal reasons.
- Preserve lease tokens, attempt-number fences and the database expiry check after row-lock acquisition.
  Replay cannot clear a live lease or make an old completion valid in a later delivery cycle.
- Keep `event_id`, endpoint ownership, payload, event type and `received_at` stable through replay.
  Destinations still need idempotent event processing; replay can repeat a previously delivered effect.
- Management currently uses `EVENTRELAY_ADMIN_TOKEN` and one implicit tenant. Scope every store access
  by that tenant. Do not label the static token as implemented M5 API-key management.
- Existing `GET /v1/events` sorts by `(received_at DESC, id DESC)`, defaults to 50, caps at 200 and accepts
  `status`, `endpoint_id` and its current cursor. Preserve its response and cursor behavior. M4 adds
  tested RFC3339 `from`/`to` filters selecting `[from,to)` and a payload-free `view=summary`.
- Destination URL updates retain delivery-time SSRF protection, direct validated-IP dialing, no redirects
  and no environment proxy. Inspecting or changing an endpoint must not initiate an outbound probe.

## Inspection and endpoint recovery

Event detail must expose current status, lifetime attempt count, replay/cycle information, current retry
time when applicable and the current terminal reason where present. Stored payload is privileged data:
do not put it in list previews, logs, browser persistence or HTML interpretation by default.

Attempt pages must show persisted attempt number, start/finish, outcome, HTTP status, duration and bounded
diagnostic error. An in-flight attempt has no invented finish time or response. M2/M3 discard destination
response bodies; `response_excerpt` is NULL. Do not fabricate response bodies, response headers or a
request header archive. Display an explicit unavailable state for evidence that was never captured.
Order attempts by stable attempt number and bound page size and response bytes.

Expose secret-free endpoint detail and a bounded PATCH sufficient to correct a URL and re-enable a
410-disabled endpoint. Define validation, concurrent updates and changes during an in-flight delivery
before implementation. A stale 410 response must not silently disable a newly corrected destination.
M4 PATCH accepts only `expected_revision`, `url` and `enabled`; it does not edit `max_attempts` or secrets.
If a later change makes budgets editable, specify which cycles use the new value and prove that reducing
it cannot strand pending events. Do not expose signing secrets through detail, list, errors or UI state.

## Replay contract

The existing worker refuses a claim when lifetime `attempt_count >= max_attempts`. Merely setting an
exhausted event to pending cannot implement replay. Cycle accounting follows accepted ADR 0006:

1. Preserve lifetime attempt numbering/history and give an accepted replay a bounded new delivery budget.
   Apply the unchanged M3 schedule to the failed attempt number within that budget. Interrupted claims
   consume the budget exactly as they do in the initial cycle.
2. Accept only explicitly documented terminal states. The accepted contract permits `delivered` and
   `dead_lettered`; `pending`, `in_flight` and `canceled` are conflicts. There is no event status `failed`.
   Missing or non-owned IDs return the same not-found response. A disabled endpoint cannot accept replay.
3. Under one fenced transaction, validate the expected replay version, archive the prior cycle/terminal
   evidence, advance replay state and set one persisted due time. Concurrent requests for the same version
   may start only one cycle. A retry of an old request cannot create an additional cycle after rapid delivery.
4. Replay records an administrative action, not an HTTP attempt. The next successful worker claim appends
   lifetime attempt `n+1` before HTTP, under the existing lease transaction.
5. Define active dead-letter membership separately from historical terminal records. Leaving the DLQ must
   not erase earlier reasons/attempts, and later exhaustion must not overwrite the only historical reason.
6. Specify counter widths, migration defaults for M3 rows, overflow behavior, lock order and mixed-version
   worker compatibility. No existing event may get a fabricated replay or duplicate attempt during upgrade.

New API errors remain RFC 9457 documents. Document status/error identifiers, replay preconditions and
response fields in OpenAPI when the handlers actually exist. The browser must display conflict results
and refresh state; it must not silently retry a replay mutation.

## Dashboard and statistics

Use an authenticated same-origin deployment/session or proxy design chosen in ADR 0006. Keep admin and
endpoint secrets out of compiled assets, URL parameters, local/session storage, analytics and logs.
Cookie-based mutation access needs origin/CSRF checks and defined expiry/logout behavior. Development
examples must use synthetic credentials and loopback; production guidance remains a separate M6 gate.

The 24-hour delivery success rate must have an explicit UTC window, numerator and denominator. The
implementation counts finished HTTP attempts with `outcome=success` over finished attempts with an HTTP response;
network/policy/lease-expiry attempts are separate counts, and the label states this denominator.
Expose source timestamps, zero-denominator/null states and partial-history limits. Compute over bounded,
indexed store queries, not by fetching every event page into the browser or assuming future metrics exist.

Provide loading, empty, error, unauthorized, stale and unavailable states, keyboard access and readable
mobile layout. Render payload/error text as text, encode identifiers in routes, and constrain any links.
Pagination bounds apply to endpoints, events and attempts, including browser memory retained across pages.
Polling must have one active request per view, cancellation on navigation and cleanup on unmount; the
chosen interval, request timeout and paused-tab behavior belong in the implemented documentation.
